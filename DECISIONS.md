# Decisions

Product calls Nina has made beyond SPEC.md. Newest last.

- **Notch on other screens.** The companion sits in the notch on the MacBook screen. When the lid is closed or the notch isn't usable, it moves to the menu bar automatically (approved fallback, SPEC section 6).
- **Quick replies to Claude Code.** Only for sessions started through Hand off, and only when it's waiting at its ordinary prompt (not a permission prompt or pick-list). The answer is typed into that session's own Terminal window, so the window never falls out of sync. Other sessions get Open only.
- **Notch companion while on an external screen.** The face stays in the notch and also appears in the menu bar of the screen in use.
- **Keyboard shortcut.** Control-Option-C opens and closes the panel.
- **Cursor is automatic, not manual** (changes SPEC section 5). Cursor's documented agent hooks report prompts, replies, questions and stops, so each Cursor agent chat becomes its own ticket. Open focuses the project's Cursor window; Cursor has no link to a single chat. Quick replies stay off for Cursor.
- **Cursor chat names** (changes SPEC section 2). Tickets show the chat's own name from Cursor ("Predictive ordering UI sweep") above Nina's latest message. The name is read from Cursor's database: read-only, one lookup by chat id, names only. If a Cursor update breaks that, tickets fall back to a name made from the chat's first message. Chat contents still come only from the hooks and the transcript file Cursor's hooks point to.
- **Cursor ticket titles** follow Nina's latest message, including words typed after a pasted page element.
- **Working rows show live activity** ("Running npm test · 12s ago"), ticking every second only while the panel is open.
- **A finished reply is Nina's turn** (replaces the earlier rule of done unless it ends on a question). When a Cursor agent finishes, its ticket waits on her, showing the start of the reply, until she presses Done. Prompting the chat again sends it back to Working. Stopping it herself counts as done; an error is blocked.
- **Panel animation.** The panel grows out of the notch and shrinks back into it. Instant when Reduce Motion is on.
- **Manual tickets** start as waiting on you. Still running moves them to Working. (To revisit once Nina has used it.)
- **When a Claude Code session stops.** Same as Cursor: a finished reply waits on Nina until she marks it Done.
- **Hand off to Claude starts Claude Code in Terminal** in the chosen project, with the brief as its first message. Needs Anthropic's Claude Code installer run once; the desktop app's own copy can't be started from outside. The session id is set up front so its ticket is the hand-off ticket.
- **Hand off to Cursor** copies the brief and opens the project. When Nina pastes and sends it, the Cursor feed takes over that same ticket.
- **Ready to delegate** is Brain → Task Tracker, tasks with a new Agent checkbox ticked and Status not Done or Cancelled. Read-only; the Notion token lives in config.local.json, set with `cr set-notion-token`.
- **Hand off remembers a default tool per project**: choosing a project switches to the tool last handed off there.
- **Devin** is checked every 30 seconds with a personal access token (`cr set-devin-token`), only Nina's own sessions from the last day. Working → Working; waiting for her or her approval → Waiting on you; finished → Waiting on you until she marks it Done; errors and credit or limit stops → Blocked. A ticket only moves when Devin's status changes, so Done sticks.
- **Quick reply labels**: YES (mint) and NOT YET for yes/no; numbered options for pick one. A failed send turns the ticket Blocked with the reason.
- **Sleeping Devin sessions stay hidden.** When Devin suspends a session for inactivity, its ticket doesn't change and a new one isn't made. Only live sessions (working, waiting, finished, errored) show.
- **End of day opens by itself at 18:30** (Nina's choice; the spec proposed 18:00), once a day, on days with something to look back on. Change it with "end_of_day" in config.local.json.
- **Drop also unticks Agent in Notion** (changes SPEC section 5's read-only rule, at Nina's choice) when the ticket came from Task Tracker. Hand off from End of day removes the put-off ticket once the hand-off starts.
- **Quiet mode** starts from QUIET in the panel header (25, 50 or 90 minutes) and survives a restart. Tomorrow 9am doesn't count as a Later.
- **Scheduled tasks are watched by hand** (v1, as the spec planned): Nina adds each one to the watch list on the board (name, Claude or Grok, time, how often, optional link). At its time a result lands as a card she reads or marks Didn't run. It counts as waiting but never wakes the companion.
- **Unread scheduled results expire when the next run of the same schedule lands**; the watch list shows "unread · Thu".
- **Calendar comes from the private iCal link of Nina's Google calendar** (the one Notion Calendar shows), set with `cr set-calendar-link` and fetched every 5 minutes. Notion Calendar itself has no way in; its Task Tracker entries are tasks, not hard stops. The hard stop is the next event today that's busy, timed, starts later and isn't declined, including repeats and moved occurrences. It shows on the board and Hand off headers, and in the panel when it's within the hour.
- **Control Room starts at login** from ~/Applications, registered once by the app itself. Turning it off in System Settings → General → Login Items is respected.
- **Cursor also runs Claude Code's hooks** (it loads ~/.claude/settings.json). The Claude Code feed ignores those events, which carry cursor_version; the Cursor feed already covers them. The Claude Code feed only makes tickets from Claude Code's own event names.
- **Open and Hand off go to Cursor's editor window**, using Cursor's own `cursor` command on the project folder, not its Agents window.
- **Claude app task sessions and Grok Bot chats are read from the files those apps keep on this Mac** (Nina chose this; both formats are undocumented). Checked every 10 seconds, read only. Claude app: working, replied (a "result" in its log) or waiting for permission; scheduled runs land as scheduled results with their text and never wake the face, and a new run replaces an unread one. Grok Bot: its own unread count marks a reply; reading it in Grok Bot clears the ticket. On first install, only chats working now or with unread Grok replies appear. Plain Claude chats with no folder or tools live only on Anthropic's servers; see the next point. `cr chats` shows what the feeds see.
- **Plain Claude chats are read from the Claude window through Accessibility** (Nina chose this, knowing it only sees the chat on screen). A reply seen being written makes a ticket; one finished while Claude isn't in front waits on her; opening the chat counts as reading it. Switching chats mid-reply leaves a ticket saying so. Chats Claude renames mid-reply keep their ticket.
- **The app is signed with Nina's Apple Development certificate** when the Mac has one, so macOS keeps Accessibility and Automation permissions across rebuilds. Without one it falls back to an ad-hoc signature.
- **The app icon is the neutral face (01), not asleep (02)** (Nina chose this). `tools/make-icon.swift` redraws the whole icon/ set from it.
- **Quiet outranks every other face**, though the companion spec lists it below alert and worried: SPEC section 4 says the face stays asleep while quiet, whatever is waiting, so it shows the quiet face.
